project is organized, what kinds of contributions are useful, and how

## Ground rules

- Be kind.  Read the Code of Conduct first.
- Open an issue before starting a large change.  Five minutes of
  discussion can save a weekend of rework.
- One change per pull request.  Small PRs get reviewed fast.
- Tests are welcome but not required for UI tweaks.  Describe how you
  verified the change instead.

## Getting set up

    git clone https://github.com/OpenNoorIlm/PyTorchUI.git
    cd PyTorchUI
    python -m venv .venv
    source .venv/bin/activate        # or .venv\Scripts\activate
    pip install -r requirements.txt

Build the node database once so the editor has something to load:

    python build.py                  # default library list
    python build.py -l torch,numpy   # smaller set for fast iteration

Launch:

    ./start.sh

## Development workflow

1. Branch off main:

       git checkout -b fix-codegen-splat

2. Edit helpers/Nodes/Nodes.py (or whichever file needs the change).
   Do not edit main.py -- it is regenerated by create.py on every
   build.

3. Restart the editor to see your change.  There is no reload; the
   editor imports everything once at startup.

4. Run the syntax check on anything you touched:

       python -m py_compile \
           helpers/Nodes/Nodes.py \
           helpers/Nodes/NodeClasses.py \
           helpers/Nodes/ConvertDialogs.py \
           helpers/Nodes/LibraryDialogs.py \
           create.py build.py start.py

5. Open the editor, load an example, press Ctrl+G and F5, and confirm
   nothing regressed.

6. Push and open a PR.

## What we are looking for

- Bug fixes with a clear reproduction.
- New node types that make a real workflow easier.
- Improvements to create.py: better type inference, more library
  filters, faster walking.
- Improvements to codegen: better handling of edge cases in
  _generate_code (auto-sentinel inputs, positional splats, Lazy
  variants, nested classes, kwargs).
- Documentation: examples, tutorials, screenshots.
- Test graphs in examples/ that exercise a feature end to end.
- New preview kinds for the Preview category.

## Adding a node type

Node templates come from one of four places:

| source | file | when |
| --- | --- | --- |
| create.py walk | generated .db | build time |
| _register_builtins(api) | Nodes.py | startup |
| _register_roles(api) | Nodes.py | startup |
| NODE_TEMPLATES.extend([...]) | Nodes.py | import |
| api.register_node(...) | any script | runtime |

For a permanent addition, extend NODE_TEMPLATES in Nodes.py.  The
shape is:

    NODE_TEMPLATES.extend([
        ("My Category", [
            {
                "name": "My Node",
                "color": "#4A6B8A",
                "kind": "my_kind",
                "description": "Markdown.",
                "inputs": [
                    ("A", "int", "First operand", "0"),
                    ("B", "int", "Second operand", "0"),
                ],
                "outputs": [
                    ("Result", "int", "A + B"),
                ],
            },
        ]),
    ])

Then add a codegen branch in _generate_code / emit_leaf:

    if kind == "my_kind":
        L.append("%s%s = (%s + %s)"
                 % (pad, var, B.get("A") or "0", B.get("B") or "0"))
        return L, miss

Restart the editor.  The node appears under My Category.

## Adding a specialised widget

To attach a Qt widget to a node (button, slider, combobox), add a
subclass factory in NodeClasses.py:

    @register_node_class("my_kind")
    def _make_my_node(Node):
        class MyNode(Node):
            def after_template_built(self, template):
                self.add_slider(0, 100, socket_name="A")
                self.add_button("Reset", on_click=self._reset)
            def _reset(self):
                s = self.socket("A", is_input=True)
                if s: s.set_value("0")
        return MyNode

Then set node_class to "my_kind" on the template, or rely on the
automatic kind match in build_node_from_template.

The full list of helpers (add_button, add_slider, add_spin,
add_combo, add_checkbox, add_line_edit, add_label, add_text_edit,
attach) lives in NodeClasses.py under _NodeWidgetHost.

## Adding a codegen branch

_generate_code in Nodes.py is where every node kind translates to
Python.  Two functions matter:

- emit(n, indent) wraps the node in a runtime.begin / runtime.end
  block for output capture.
- emit_leaf(n, indent) is the actual Python for the node's action.

Find an existing branch that resembles what you want.  Most fall into
one of these patterns:

| pattern | example |
| --- | --- |
| Simple call | pyautogui.click(x=..., y=...) |
| Split call + assignment | nn.Conv2d(...), then model(tensor) |
| Module import | import torch when torch.* is used |
| Expression template | ({A} + {B}) for a binop node |

Add yours by checking if kind == "your_kind": and appending to the
line list L.  Return (L, missing) where missing is a list of input
names that had no value and no connection.

## Testing

There is a tests/ directory, currently minimal.  Useful things to
test:

- create.py walking a small package (math, json).
- _generate_code on the example graphs.
- Round-trip: save a graph, load it, compare the dicts.
- _safe_nid returning stable ids across reloads.

Run:

    pytest tests/

## Code style

- Python 3.9+ syntax.  No type annotations required, but welcome
  where they clarify.
- Four-space indents.  Lines under 100 characters.
- Comments explain why, not what.
- No new third-party dependencies without a discussion first.
- Prefer stdlib over a new dependency.

Nodes.py is one very large file.  It works because it keeps the
editor, scene, codegen, and API in one place with no import dance.
If you need to add something substantial, consider a new module under
helpers/Nodes/ (like ConvertDialogs.py) rather than growing Nodes.py.

## Commits

- One logical change per commit.
- First line under 72 characters, imperative mood
  (fix codegen for auto-sentinel, not fixed).
- Reference the issue if there is one.

## Pull request checklist

- [ ] One change per PR.
- [ ] python -m py_compile passes on every modified file.
- [ ] The editor starts and the modified feature works.
- [ ] Ctrl+G produces valid Python for a graph that uses the changed
      node.
- [ ] F5 runs that Python without error.
- [ ] No new files that should not be tracked (check .gitignore).
- [ ] Commit message describes why, not just what.

## Reporting bugs

Open an issue and include:

- What you did.
- What you expected.
- What actually happened.
- The full traceback.
- The output of python -c "import sys; print(sys.version)".
- The output of python -c "import torch; print(torch.__version__)".
- Whether the bug is reproducible on a fresh clone.

If the bug is in codegen, paste the offending line from generated.py.
